# GedaTv audit — October 2026

Branch `audit/2026-10-improvements`, cut from `main` at `20b38ce`. The starting
point is tagged `pre-audit-2026-10` (local tag). Nothing here has been
committed or deployed yet.

"Prod" means https://gedatv.netlify.app as of 16 Oct 2026. "Local" means
`next build && next start` on this machine. Local numbers are never presented
as production numbers.

## A. Audit summary

### What was inspected
- All of `src/` (routing, server pages, client components, `lib/`), `next.config.ts`, `netlify.toml`, `public/sw.js`, `package.json`, git history and `docs/REDESIGN.md`.
- The production site with curl (HTML/JS sizes, compression, cache headers, TTFB) and the in-app browser (DOM, localStorage, iframes, console).
- A local production build in the browser: My List, favourites, history, cross-tab sync, the player with all 11 sources, episode navigation, the trailer dialog, keyboard focus, mobile width, client-side navigation and search.
- `next build`, `tsc --noEmit`, `eslint`, `npm audit`.

### What was already working well
- TMDB layer: parallel fetching on every catalogue page, in-flight deduplication, a 30-minute in-memory cache plus `revalidate: 3600`, and slim list/detail payloads (`toListItem`, `slimDetailsForClient`).
- ISR is set up correctly. One cached watch page serves every `?s=&e=&server=` combination because those params are read on the client.
- Compression is effective. Home is 653 KB raw but 52 KB with Brotli.
- The earlier "94% fewer buttons" claim holds: home has 47 `<button>`s. Card actions mount on hover.
- The TMDB API key is not in any client bundle. It is read on the server only.
- Reduced-motion CSS covers both the OS setting and a `data-motion` hook.

No dependencies were added or removed. The video source list (`src/lib/videoSources.ts`) and all TMDB methods are unchanged.

**Data decisions.** My List now reads the profile-aware library (`gedatv_v3`). Every write is still mirrored to `gedatv_watchlist`, so the previous build keeps working on the same data if you roll back. The legacy merge only adds titles. A title someone removed on a title page before this fix (which removed it from the legacy list only) can therefore still be in the library and stays there. I chose the occasional resurfaced title over any chance of losing saved ones.

## F. Deployment and rollback

- **Deploy?** Yes, after you review the diff. The changes are front-end and server-render only, with no config or environment changes. Netlify builds from `main` with `npm run build`.
- **Environment variables:** none added or changed. `TMDB_API_KEY` must stay server-only. Don't add a `NEXT_PUBLIC_TMDB_API_KEY`: `tmdb.ts` still falls back to it, and a `NEXT_PUBLIC_` value is inlined into any browser bundle that imports the file. Since this change no client component imports `tmdb.ts` at runtime (verified: none of `.next/static` contains its fetch code), but the fallback is still a trap.
- **Data:** the one-time merge adds a single `gedatv_legacy_watchlist_merged` key per browser and only adds titles. The legacy keys keep receiving every write.
- **Rollback:** redeploy the previous Netlify deploy from the dashboard (instant), or `git revert` the merge commit. Locally, `git checkout pre-audit-2026-10` is the exact starting point. Data written by the new build stays readable by the old one, because both stores keep being written.

## G. Follow-up: first-load speed and no motion (16 Oct 2026)

Request: load fast on a new device or browser, with no flashy animations or transitions.

Measured with Lighthouse 12.6.1 in mobile mode with **real (DevTools) throttling**: slow 4G, 4× CPU, Moto G-class screen. Lighthouse's default *simulated* mode overstated LCP on localhost, so it isn't used for comparisons. "Before" is the live site. "After" is a local `next start` of this change, so it has no server latency; expect roughly 0.4–1 s more on Netlify.

| Home page | Before (prod) | After (local) |
|---|---|---|
| Performance score | 61 | **91** (3 runs: 91 / 91 / 91) |
| First contentful paint | 2.7 s | 1.9 s |
| Largest contentful paint | 3.6 s | **2.5 s** |
| Total blocking time | 1,340 ms | **250 ms** |
| Bytes downloaded | 4.7 MB | **1.17 MB** |
| DOM nodes | 4,321 | **2,102** |
| HTML (raw / gzip) | 653 KB / 68 KB | 407 KB / 59 KB |

Title page `/watch/movie/550`: score 69 → 91, LCP 5.4 s → 2.6 s, 3.0 MB → 0.78 MB. `/movies`: score 59 → 95, LCP 3.9 s → 2.3 s.

What caused the slow first load, and what changed:

| Cause (measured) | Fix |
|---|---|
| All four icons were the same 1024 px JPEG (359 KB) saved as `.png`. The browser fetched it 5 times, about 1.8 MB per first visit. | Real PNGs at their declared sizes: 96 px favicon 5 KB, 180 px apple icon 14 KB, 192 px 16 KB, 512 px 87 KB. |
| Card posters had a `srcset` but no `sizes`, so phones downloaded the 500 px poster for a 135 px card. | `sizes` per card layout. Phones now get 342 px posters. |
| The navbar sat in a `Suspense` with `fallback={null}` because it uses `useSearchParams`, so it wasn't in the server HTML and only appeared after hydration. It was the LCP element, at 3–17 s. | Only the `?q=` sync lives in its own `Suspense` (`SearchQuerySync`). The navbar is server-rendered. |
| About 180 cards rendered and hydrated on the home page. | `MovieRow` renders 10 cards, then adds more as the row scrolls (`renderCount`). Off-screen rows use `content-visibility: auto`. |
| Top 10 posters were `loading="eager"`, which React turned into head preloads competing with the hero image. | All lazy. |
| Inter (48 KB) and Manrope were both preloaded and competed with the stylesheet and hero image. | Body text uses the device's system UI font. Manrope stays for headings. |
| The hero preloaded the next slide's 1280 px backdrop and auto-rotated every 8 s. | No autoplay and no next-slide preload. The arrows and indicators remain. |
| `got-scraping` was imported at module scope in the shared server-actions file. | Imported on demand inside the Moctale reviews action only. |

Motion removed: Framer Motion is uninstalled (watch-page tabs, dropdowns, studios/people/awards/search grids, reviews, offline page). Also gone: the flying-heart effect (`FlyingParticles`, `ClientOnlyComponents`), page fades, entrance animations, Ken Burns zoom, scroll reveals, skeleton shimmer, hover lifts and zooms, smooth scrolling and every `backdrop-blur`. `globals.css` sets `animation: none; transition: none` on all elements. The only exception is the `.animate-spin` loading spinner.

Tried and reverted: `experimental.inlineCss`. Next inlines the CSS twice (in a `<style>` tag and in the RSC payload), so home HTML went from 59 KB to 116 KB gzip and LCP from 2.5 s to 5.5 s.

Checked after the change: the hero stays on slide 1; rows grow from 12 to 20 cards on scroll; Episodes, Details, More like this, Photos and Reviews tabs all work; the season dropdown opens; the player shows its spinner and loads the source; no element on the home page has a running animation or transition; no console errors. `next build` and `tsc` pass, and eslint has 0 errors and 40 warnings (the baseline).
